Codezzn × RAGFlow 四阶段测试手册

目标：在保留本地 Milvus 回滚能力的前提下，让 RAGFlow 成为可选择、可对照评测、可切换的知识检索后端。

双后端异步解析混合检索可回滚

开始前

  1. 独立启动 RAGFlow，并在其界面配置可用的 Embedding 模型。
  2. 在 RAGFlow 获取 API Key。
  3. 将以下值写入 Codezzn 的现有 .env，不要覆盖其他密钥。
CODEZZN_KNOWLEDGE_BACKEND=local
CODEZZN_RAGFLOW_URL=http://host.docker.internal:9380
CODEZZN_RAGFLOW_API_KEY=你的RAGFlow密钥
CODEZZN_RAGFLOW_TIMEOUT=120

如果 RAGFlow 与 Codezzn 在不同 Docker 网络中，必须使用 Codezzn 容器实际可访问的地址；容器内的 127.0.0.1 指向 Codezzn 自己。

阶段一：验证后端抽象

目的：确认旧知识库继续使用本地 Milvus，新知识库可以明确选择 RAGFlow。

  1. 重建并启动 Codezzn。
  2. 打开“知识库”，确认编辑页出现“后端类型”。
  3. 打开已有知识库，确认显示“本地 Milvus”。不要直接将有数据的旧知识库改成 RAGFlow。
  4. 运行离线测试。
docker compose up -d --build
docker compose exec -T codezzn python -m pytest -q -p no:cacheprovider tests/test_core.py tests/test_ragflow.py

通过标准：旧本地知识库检索正常；RAGFlow 客户端测试通过；Agent 与 Workflow 都通过统一检索服务调用。

阶段二：验证 RAGFlow 测试知识库

  1. 新建知识库，后端选择 RAGFlow。如果没有数据集 ID，先保存并点击“创建数据集”；也可以在 RAGFlow 创建后手工填写 ID。
  2. 点击“上传文档”。返回 processing 表示已提交，不表示索引完成。
  3. 点击“文档状态”，轮询到 DONE；若为 FAIL，查看 progress_msg 和 RAGFlow 日志。
  4. 点击“测试检索”，确认结果带有 ragflow-hybrid 标识、来源和分数。
  5. 给 coding agent 勾选该知识库与 knowledge_search，然后发起文档相关问题。
curl -H "X-Codezzn-Key: $CODEZZN_ADMIN_KEY" \
  http://127.0.0.1:8080/api/knowledge/你的知识库ID/health

通过标准：健康检查成功；文档完成解析；直接检索、Agent 自动检索、Agent 工具检索均能返回同一来源。

阶段三：双跑对照评测

准备一份本地知识库和一份 RAGFlow 知识库，尽量导入相同原始文件。为每个问题填写期望来源文件名。

curl -X POST http://127.0.0.1:8080/api/knowledge/evaluate \
  -H "Content-Type: application/json" \
  -H "X-Codezzn-Key: $CODEZZN_ADMIN_KEY" \
  -d '{
    "local_knowledge_ids":["本地知识库ID"],
    "ragflow_knowledge_ids":["RAGFlow知识库ID"],
    "top_k":5,
    "cases":[
      {"query":"退款期限是多少？","expected_sources":["policy.md"]},
      {"query":"如何启动沙箱？","expected_sources":["manual.pdf"]}
    ]
  }'

Hit@K

Top-K 中是否至少命中一个期望来源。

MRR

正确来源越靠前，分数越高。

来源 Recall@K

多个期望来源被召回的比例。

平均延迟

两种后端的平均检索耗时。

当前评测以“文件名”为 Ground Truth，适合迁移验收，但还不是完整的 Chunk 级 NDCG/Faithfulness 评测。

阶段四：切换默认后端与回滚

  1. 只有在阶段三的真实业务问题评测通过后，才把 CODEZZN_KNOWLEDGE_BACKEND 改成 ragflow。
  2. 重启后，该值只影响新建知识库；已有知识库的 backend 不会被偷偷改变。
  3. 逐个把 Agent 的 knowledge_ids 从旧本地知识库改为已验证的 RAGFlow 知识库。
  4. 至少保留旧知识库一个稳定周期，不删除 SQLite、Milvus 数据或原文。
CODEZZN_KNOWLEDGE_BACKEND=ragflow
docker compose up -d --build

回滚：把 Agent 的 knowledge_ids 重新指向旧本地知识库，并将默认值改回 local，然后重启。无需转换或删除数据库。
