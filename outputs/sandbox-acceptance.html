实现范围

每次 Shell/Git 工具调用创建一个独立 Linux 容器，而非整个 Turn 共用容器。主应用不挂 Docker socket；独立 broker 管理创建、状态持久化、超时、取消、销毁及启动回收。

配置默认值
执行身份10001:10001，禁止 root
挂载仅 /workspace；只读根文件系统；/tmp 为 64 MiB 临时内存盘
网络none，固定关闭
资源1 CPU / 512 MiB 内存与总内存交换上限 / 64 PID
超时60 秒，broker 截止时间 + 容器 PID 1 独立看门狗
清理正常、失败、超时、取消均删除；失败标记 cleanup_pending，阻止新任务并重试
恢复本实例标签过滤；重启标记 interrupted 并回收遗留容器

启动步骤（PowerShell）

进入项目目录。保留现有 .env，不要覆盖。生成两个不同随机值，分别填入 CODEZZN_SANDBOX_TOKEN（至少32字符）和 CODEZZN_ADMIN_KEY。不要把密钥放到 workspace。

cd D:\code-agent-rag-workflow
# 可用的 Python 环境中生成随机密钥，两次使用不同值
python -c "import secrets; print(secrets.token_urlsafe(32))"

docker build -f Dockerfile.sandbox -t codezzn-sandbox:local .
docker compose -f docker-compose.yml -f docker-compose.sandbox.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.sandbox.yml ps

如需在执行容器中跑 pytest，构建时加 --build-arg INSTALL_PYTEST=true。项目其他依赖也需在镜像构建时安装，运行时不允许联网下载。

若 docker compose 不存在，请在有 Compose 插件的 Docker Desktop 终端执行。这里已验证 Docker 引擎，但组合部署未在当前 CLI 验证。

配置智能体与检查

{
  "sandbox_mode": "read-only",
  "allow_shell": true,
  "auto_approve": true,
  "builtin_tools": ["run_shell", "git_status", "git_diff", "git_log"]
}

这里只对测试 Agent 开启上述工具；不要开启 danger-full-access，也不要混入不需要的 MCP/原生写文件工具。当前审批续跑不在本次范围，auto_approve 用于允许已经受容器策略约束的工具执行。改为 workspace-write 才能在挂载工作区写入。

$headers = @{ "X-Codezzn-Key" = "你的管理密钥" }
Invoke-RestMethod -Headers $headers http://127.0.0.1:8080/api/sandbox/status

docker compose -f docker-compose.yml -f docker-compose.sandbox.yml logs --tail=100 sandbox-broker

让 Agent 执行 id; python --version，应显示 uid=10001。状态中检查 ready、status、exit_code、cleanup_pending。只读模式写文件应失败；工作区可写模式仍需宿主机权限允许 UID 10001 写入，不要改为 root 或 chmod 777。

边界与未覆盖事项

  • broker 持有 Docker socket，具有宿主机管理员级权限，仅供可信单机部署，不是多租户安全边界。
  • Shell/Git 已隔离；原生 Python 文件工具、MCP 仍属于主服务信任域，不是所有 Agent 行为都已隔离。
  • 共享工作区没有磁盘/inode 配额、分支隔离或多文件回滚；写入仍能覆盖/删除工作区内容。原生文件工具并发路径竞态不在此轮修复范围。
  • Docker 引擎不可用时无法立即删除容器；恢复后回收，任务不能回退到宿主机执行。
  • 固定 UID 10001 与宿主机目录权限需要匹配；工作区中不要保存密钥。
  • 为消除主进程 patch 子进程入口，统一 Diff 输入暂时明确拒绝，精确 old/new 替换保留。
  • 未改动现有 .env、业务数据库；未重启现有业务容器。完整 Compose 部署需用户在可用的 Compose 环境完成。
