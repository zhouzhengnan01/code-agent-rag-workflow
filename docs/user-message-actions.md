# 用户消息操作

桌面聊天页在用户消息右下角提供悬停操作栏。发送时间使用浏览器本地时区，悬停时间显示完整日期；复制按钮复制原始消息文字，不包含 Markdown 渲染产生的按钮、时间或附件名称。支持 Clipboard API，并为局域网 HTTP 提供传统复制回退；复制失败会明确提示。

编辑在原消息位置展开多行输入框。取消不提交；“重新发送”通过现有持久队列生成新消息，保留原消息、后续回复、审批和已执行任务记录，不回滚文件，不自动批准或打断任务。重新发送沿用当前智能体/项目和原消息附件，不覆盖主输入框中的未发送草稿。正在提交和提交结果不明时禁止重复提交。

轮询不会替换正在编辑的输入框。编辑内容仅作为当前浏览器内的草稿，不直接更新数据库历史。新队列消息记录 sent_at 为入队时间，避免排队后才执行造成时间显示偏差；旧消息优先使用可用的队列时间，否则使用其已有的消息时间，缺失时间明确显示未知。

验收：41 项聊天前端 Node 测试通过；隔离、禁网 Docker 回归 66 项通过（会话、附件、确认卡片、工程面板及 Chromium 消息交互）。Windows Edge 额外验证正常复制和模拟 HTTP/权限失败后的复制回退、悬停显示、就地编辑、取消不提交、轮询保留草稿、重新发送一次且不改历史。浏览器测试使用隔离 API fixture，不调用实际模型或批准用户任务。
