# 截图保存与审批续跑修复（2026-10-12）

这次诊断针对用户的 Hello 算法仓库测试，读取了对应租户的消息、工具流水线、审批和检查点，并核对实际文件。

## 发现

1. `screenshot` 工具确实创建了 `hello-algo-github.png`（1,387,694 字节），但当轮没有项目保存确认。浏览器工具写进了会话工作区根目录，未登记项目或对话产物；模型却说保存在当前项目。后续文件检索以选中项目为根，因而找不到。
2. “重新截图”选项已经被接收，审批状态是 `approved`。续跑先遇到同名文件存在，随后成功创建 `hello-algo-github-2.png`（189,020 字节）。之后请求了 `browser_get_state(include_screenshot=true)`；调用链给模型追加了图片观测。
3. 当时使用的 `qwen3.7-max` 当前端点经小尺寸合成图片实测，返回 HTTP 400：`Unexpected item type in content.`，说明该配置拒绝图片内容块。该结果与当轮最后一次带图观测及随后 502 一致；旧版本没有持久化那次 502 的原始响应，无法逐字追溯原错误。
4. 前端遇到续跑 502 后重新启用了旧选项。再次点击才得到“审批已处理”。因此该 409 是重复提交已消费审批的结果。旧版本还遗留了 running 的 Agent run 与 failed 的检查点，存在重启时误恢复的风险。

## 修改

- 截图请求使用确定性的产物意图，明确走项目保存选择；仅启用浏览器的 Agent 也能按相应权限保存截图，无需添加代码写入工具。
- 已确认项目保存的截图写入项目并登记；未关联项目的浏览器输出登记为对话产物，返回真实下载地址和存储范围。
- 对话中提供截图缩略预览、查看大图及下载。Files 面板能查看对话产物，项目 PNG/JPEG/WebP 支持大图预览。预览与下载携带认证头，检查租户、归属、路径及符号链接。
- 向模型提供已登记截图信息，展示已有文件时无需盲目重拍。当前模型/回退模型不支持图片时，浏览器状态使用 DOM 文本，不追加图片内容块；图片文件仍可向用户展示。
- 续跑发生错误时记录实际错误、失败状态及用户可见结果。回答已消费后前端刷新会话，不重启旧按钮；正在提交时防止重复点击和切换任务。
- 启动时把 failed 检查点对应的旧 running/waiting Agent run 修正为 failed，避免自动恢复这类已失败任务。
